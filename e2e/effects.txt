# The effect log: everything that has left the process —
# every job the app filed on the outside world, its status, the sentence
# the effect describes itself with and the JSON it was filed as unfolded in
# place, and beside those the in-memory effects nobody files, joined in
# from the ring.
#
# It opens narrowed to `@wrote`, typed into its own field: a sync pass asks
# the outside a dozen questions for every answer it acts on, so the reads
# are on request rather than by default.
#
# Run with --send-delay 1. The demo account has no SMTP host, so a send is
# the shortest honest way to put a real job in this queue: it is submitted,
# it fails, and the log is where that failure is legible.
wait 700

# The launcher finds the panel under the word one actually reaches for.
key cmd 2
wait 400
type "log"
wait 400
shot g1-launcher
key enter
wait 800
# Nothing has been changed out there yet — said, rather than left blank,
# and said under the default the field is holding. (In a run that takes
# pictures the runner's own `shot` has already changed something: a
# screenshot is an effect like any other, and a write. The gate runs
# `--no-draw`, which takes none.)
shot g2-empty
key cmd+w
wait 600

# File a send against an account with nowhere to send it.
click "Q3 infra"
wait 600
click "reply"
wait 500
type "Checking egress today."
wait 300
click "send"
wait 2500

# Back to the log: one job, and the server's own words under it.
key cmd 2
wait 300
type "effects"
wait 400
key enter
wait 900
shot g3-log
# A row is addressed by the sentence its effect describes itself with —
# so a log that stopped naming its jobs fails the run, no picture needed.
# Touching it previews the job beside the list, joined, the way an inbox
# row previews its mail; the list keeps the keyboard.
click "submit outbox:"
wait 700
shot g4-previewed

# The job panel is the whole row: its facts, the payload it was filed as,
# the answer. All of it selectable — a payload is something one copies
# into a bug report.
click "job payload"
wait 300
key cmd+a
wait 400
shot g5-payload-selected

# The filter is the rich table's, over the log's own columns. A row is
# what the keyboard comes back to first: the payload click above handed it
# to the job panel, and the inbox one column over wears a filter field of
# its own, so `click "filter"` alone would not say whose. Touching the log's
# own row does, and `/` from there is unambiguous. (The cursor walk wants
# more than one job; the panels library's effect-log scene plants five and
# walks them.)
click "submit outbox:"
wait 400
key /
wait 300
key cmd+a
type "@"
wait 400
shot g6-tags
# The offer is *clicked*, not photographed: a box that never opened has no
# such row, and the run fails there rather than in a picture nobody reads.
# `@wrote` is the one the panel opened on, so taking it changes nothing —
# which is the point: the row afterwards proves the pick landed.
click "@wrote"
wait 500
click "submit outbox:"
wait 500
# esc puts the offer away and the field keeps the keyboard — which is what
# the typing after it proves.
click "submit outbox:"
wait 400
key /
wait 300
key cmd+a
type "@"
wait 400
key esc
wait 200
key cmd+a
type "@kind:submit"
wait 500
key esc
wait 400
shot g7-kept
# Still addressable: which is how the run knows the filter was typed into
# the log's own field, and that it kept this row.
click "submit outbox:"
wait 500

# The other half of the log: the effects nobody files. cmd+i copies this
# panel's own context, which is a clipboard write — it leaves the process,
# so the ring keeps it and the log shows it beside the queue, under the
# same filter grammar. No row was written for it, which is what `@memory`
# asks about. It is a *write*, so the panel's own default would have kept
# it; asking for the ring alone is what this narrows to.
key cmd+i
wait 600
click "submit outbox:"
wait 400
key /
wait 300
key cmd+a
type "@memory"
wait 500
key esc
wait 600
shot g8-in-memory
# Addressable by its own sentence, like any other row — and it previews
# into the same job panel, which says where it lives instead of showing a
# payload it never had.
click "copy panel context"
wait 700
shot g9-in-memory-previewed
click "job facts"
wait 400
shot g10-in-memory-facts

# And the default is a default, not a rule: cleared, the log is everything,
# the reads a sync makes included. This account never reaches a server, so
# there are none to show here — the panels library's effect-log scene has
# the pair — but the clipboard write is still on the list, which is how the
# run knows the field was cleared and the list widened rather than changed.
click "copy panel context"
wait 400
key /
wait 300
key cmd+a
key backspace
wait 500
key esc
wait 600
shot g11-everything
click "copy panel context"
wait 600

# A filter nothing answers says so rather than showing a blank list.
key /
wait 300
key cmd+a
type "@kind:move"
wait 500
key esc
wait 500
shot g12-none
quit
