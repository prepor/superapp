# Read-only content is selectable. This is a --front suite: the result is a
# grey wash, and occluded windows present stale frames. (The display must
# also be awake — a slept one cannot create the window at all, which reads
# as every shot failing.)
#
# What each half checks:
#
#   `drag` only checks that the text can be found and dragging does not break
#   anything. It does not prove that a selection appears because this test
#   cannot reproduce the platform's full pointer handling. Only a real mouse
#   or e2e/cgpost.c can do that.
#
#   `cmd+a` is the REAL ASSERTION. Keyboard selection needs no capture, so
#   the wash it leaves is the proof that SText selects, renders its wash,
#   and does so inside a PortalList item.
wait 900

click "Q3 infra"
wait 700
shot s1-message

# Drag across the body: the first line should end up washed.
drag "mail body" 420 0
wait 400
shot s2-body-selected

# The headers are selectable too — addresses are the thing people copy.
drag "mail to" 200 0
wait 400
shot s3-to-selected

# Settings account rows: the same inside a PortalList, whose item areas can
# go stale during a gesture.
key cmd 2
wait 400
type "settings"
wait 300
key enter
wait 700
drag "local demo" 160 0
wait 400
shot s4-account-selected

# Selection by keyboard needs no finger capture, so it is the part the
# harness can actually prove: focus a run, select all, look for the wash.
# (Settings claims no cmd+a: its one accelerator is the add-account link,
# and that took the `d` of "add" precisely so these rows keep select-all.)
click "local demo"
wait 300
key cmd+a
wait 400
shot s5-account-select-all
quit
